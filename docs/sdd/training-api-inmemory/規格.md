# 提案 2：training-api-inmemory

五支 Training CRUD API，資料存在記憶體 list，不接資料庫。

## 目標

跑通 request → Pydantic 驗證 → 處理 → response 這條路徑，
不被資料庫的 session 生命週期干擾。提案 3 再換成 PostgreSQL。

## 不做

資料庫、前端畫面、認證、Training Plan、部署。

## 資料模型

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `id` | int | 後端產生 | 從 1 開始遞增 |
| `date` | date | 是 | 訓練日期 |
| `type` | `TrainingType` | 是 | 見下表 |
| `duration` | int | 是 | 分鐘 |
| `distance` | float | 否 | 公里 |
| `average_heart_rate` | int | 否 | 每分鐘心跳 |
| `menu` | str | 視 `type` | 訓練項目，多行文字 |
| `effort` | `Effort` | 否 | 自覺強度 |
| `note` | str | 否 | 自由備註 |

### TrainingType

| 值 | 顯示 | 需要 `menu` |
|---|---|---|
| `badminton` | 羽球 | 否 |
| `running` | 路跑 | 否 |
| `hiit` | HIIT | 是 |
| `emom` | EMOM | 是 |
| `strength` | 重訓 | 是 |
| `mixed` | 綜合 | 是 |

### Effort

`very_hard` 非常累、`hard` 累、`normal` 一般、`easy` 輕鬆。

### menu 驗證

嚴格雙向檢查，違反回 422：

- `type` 需要 `menu` 卻沒給 → 錯誤。
- `type` 不需要 `menu` 卻給了 → 錯誤。

理由：這些資料要拿來分析，不允許出現「羽球紀錄帶著重訓菜單」這種矛盾狀態。

`menu` 存教練給的原始課表文字，原樣保留不做結構化：課表格式不固定
（重量寫區間、組數格式每項不同、單位混用、附帶條件式備註），
硬要結構化會丟失資訊且 schema 追不上。

## API

| Method | Path | 說明 | 成功狀態碼 |
|---|---|---|---|
| GET | `/trainings` | 列出全部 | 200 |
| GET | `/trainings/{id}` | 取單筆 | 200 |
| POST | `/trainings` | 新增 | 201 |
| PUT | `/trainings/{id}` | 整筆更新 | 200 |
| DELETE | `/trainings/{id}` | 刪除 | 204 |

找不到 `id` 一律回 404。

## 儲存

module 層級的 list 加一個遞增計數器，不包成 class。
程序重啟資料就消失，這是這個提案接受的限制。
