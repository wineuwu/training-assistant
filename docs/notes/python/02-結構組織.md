# 02 結構組織

程式長大之後怎麼分：class、module、例外、型別標註。

## class

```python
class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):
        return f"{self.name}：汪"

d = Dog("旺財")     # 沒有 new
```

| JS | Python |
|---|---|
| `constructor` | `__init__` |
| `this`（語言給的） | `self`（每個方法第一個參數要明寫） |
| `new Dog()` | `Dog()` |
| `class Dog extends Animal` | `class Dog(Animal)` |

`self` 要自己寫在參數列是最常忘的一點。呼叫時不用傳，Python 會自動把
實例塞進去——`d.bark()` 實際上是 `Dog.bark(d)`。

### 什麼時候該用 class

判準是**有沒有狀態，會不會有多份**。

```python
class Stopwatch:
    def __init__(self):
        self.elapsed = 0        # ← 狀態：每個碼錶記自己的
    def tick(self):
        self.elapsed += 1
```

需要「多個獨立實例各記各的」，class 才划算。

### 什麼時候不該用

純轉換、沒有狀態的東西就寫函式：

```python
# 好
def format_duration(minutes):
    return f"{minutes // 60}小時{minutes % 60}分"

# 不必要
class DurationFormatter:
    def format(self, minutes): ...
```

Java 沒有自由函式，所有東西都得住在 class 裡，於是產生一堆
`XxxManager`、`XxxHelper`、`XxxUtils` 這種只是拿來裝函式的空殼。
**Python 不需要，module 本身就是命名空間。** 那些在 Python 裡是壞味道。

### 沒有 def 的 class

有些 class 裡一個方法都沒有，只有欄位：

```python
class Training(BaseModel):
    date: date
    duration: int
```

這種不是「有行為的物件」，而是**用 class 語法宣告一張結構表**，
比較接近 TypeScript 的 `interface`。Python 沒有 interface 語法，
所以函式庫（Pydantic、SQLAlchemy、dataclass）都借用 class 來做這件事。

**看 class 裡有沒有 `def`，就知道是哪一種。**

### dict 還是 class？

| 情況 | 選 |
|---|---|
| 臨時裝幾個值、形狀會變 | dict |
| 固定欄位、多處使用、想要 `.` 存取 | class（或 Pydantic model） |
| 要驗證、要轉型 | Pydantic model |

dict 的取值只能 `d["key"]`，打錯字要執行到才發現；class 的 `obj.key`
編輯器會自動完成，打錯會即時標紅。欄位固定的東西用 class 比較安全。

## module 與 import

**一個 `.py` 檔就是一個 module**，檔名就是 module 名。

```python
# main.py 裡面
from main import Training      # main 是 module，Training 是裡面的東西
```

**module 和 model 是兩個字，中文都常譯成「模組／模型」，容易混：**

| 英文 | 是什麼 |
|---|---|
| module | 一個 `.py` 檔，程式碼的容器（JS 模組化對應這個） |
| model | 一份資料的形狀定義 |

### import 的幾種寫法

```python
import math                     # 整包進來，用 math.sqrt()
from math import sqrt           # 只拿一個，用 sqrt()
from math import sqrt, floor    # 拿多個
from math import sqrt as s      # 改名，對應 JS 的 as
```

**沒有 `export`。** Python 的 module 裡所有頂層名字預設都可以被 import，
不需要標記匯出。底線開頭（`_helper`）是「內部用」的慣例，但不強制。

### import 順序慣例

分三組，中間空行：

```python
from datetime import date       # 標準庫
from enum import Enum

from fastapi import FastAPI     # 第三方套件
from pydantic import BaseModel

from models import Training     # 自己的程式碼
```

這個不用手動排，formatter 會處理（見 `03-工具鏈.md`）。

### module 層級的程式碼會執行

檔案被 import 時，裡面**沒有縮排的程式碼會立刻跑一次**：

```python
# config.py
print("載入了")          # import config 的時候就會印
CONFIG = load()          # 也會執行
```

Python 會快取，同一個 module import 兩次只會執行一次。

**`if __name__ == "__main__":`** 用來區分「被執行」和「被 import」：

```python
def main():
    ...

if __name__ == "__main__":      # 只有直接 python this.py 才跑
    main()
```

直接執行時 `__name__` 是 `"__main__"`，被 import 時是 module 名。
用途是讓同一個檔案既能當工具被引用，也能自己跑。

## 例外處理

```python
raise ValueError("訊息")        # JS 的 throw

try:
    do_something()
except ValueError as e:         # JS 的 catch
    print(e)
except (KeyError, TypeError):   # 接多種
    ...
else:                           # 沒出錯才跑
    ...
finally:                        # 一定會跑
    ...
```

`raise` 會立刻中斷函式往外拋，**後面的程式碼永遠跑不到**
（編輯器通常會標灰）。

### 常見的內建例外

| 例外 | 什麼時候 |
|---|---|
| `ValueError` | 型別對但值不合理（負數的年齡） |
| `TypeError` | 型別就不對（把 str 當數字加） |
| `KeyError` | dict 取不存在的 key |
| `IndexError` | list 索引超出範圍 |
| `FileNotFoundError` | 檔案不存在 |

自訂例外就繼承 `Exception`：

```python
class TrainingNotFound(Exception):
    pass
```

### 什麼時候該接，什麼時候該讓它炸

**該接：** 你知道怎麼處理，而且處理完程式能繼續正常運作。
例如「檔案不存在就用預設值」、「API 逾時就重試一次」。

**該讓它炸：** 你接了也不知道能做什麼。硬接下來只會讓錯誤延後爆發，
而且爆在離原因很遠的地方，更難查。

**絕對不要：**

```python
try:
    ...
except:         # 什麼都接，連 Ctrl+C 都接
    pass        # 而且吞掉不留痕跡
```

這會讓 bug 完全消失在視野裡。要接也至少寫清楚接什麼、記錄下來。

### 後端的例外處理

在 FastAPI 這類框架裡，**業務邏輯丟出的例外由框架翻譯成 HTTP 回應**。
你的驗證邏輯只管丟 `ValueError`，不用認識 HTTP 狀態碼——
這種「業務邏輯不碰協定」的分工，是後端分層的基礎。

## 型別標註

```python
def greet(name: str) -> str:
    return f"你好，{name}"

count: int = 0
items: list[str] = []
```

**標註不會被執行期檢查。** 傳錯型別 Python 照跑不誤：

```python
greet(123)      # 不會報錯，回傳 "你好，123"
```

它的用途是給**編輯器和工具**看的：自動完成、重構、靜態檢查。

### 三種「檢查」要分清楚

| 工具 | 什麼時候檢查 | JS 對應 |
|---|---|---|
| 型別標註本身 | 不檢查，只是註解 | — |
| mypy / Pyright | 寫程式時（靜態） | `tsc` |
| Pydantic | 執行時（runtime） | zod / yup |

**後端為什麼需要 Pydantic：** 外部送進來的 JSON 是執行期才拿到的，
靜態檢查管不到。必須在 runtime 真的擋，不合法的資料才不會進到系統裡。

### Optional 的寫法

```python
name: str | None = None
```

`|` 是聯集型別，對應 TS 的 `string | null`。

**必填／選填跟 `|` 無關，看有沒有預設值：**

```python
x: int                  # 必填
x: int | None           # 還是必填！只是允許傳 None
x: int | None = None    # 選填
```

TS 的 `x?: number` 把「可省略」和「可能是 undefined」寫在一起，
Python 拆成兩個位置。表達力更精確，但一開始容易搞混。

### 常用的標註寫法

```python
list[int]                   # int 的 list
dict[str, int]              # key 是 str、value 是 int
tuple[int, int]             # 剛好兩個 int
Callable[[int], str]        # 吃 int 回 str 的函式
Any                         # 放棄檢查，少用
```

後三個要 `from typing import ...`，前兩個 Python 3.9 之後內建。
